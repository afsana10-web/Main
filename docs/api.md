# PARAKH — API Reference

Full interactive documentation (Swagger/OpenAPI) is auto-generated by
FastAPI and available at **`/docs`** (Swagger UI) and **`/redoc`** once the
backend is running. This file is a quick reference.

Base URL (local dev): `http://localhost:8000`

All endpoints except `/api/auth/login`, `/api/auth/register`, and `/` require:

```
Authorization: Bearer <jwt_token>
```

## Auth

| Method | Path | Description |
|---|---|---|
| POST | `/api/auth/login` | `{officer_id, password}` → `{access_token, token_type}` |
| POST | `/api/auth/register` | Create a user (open in this prototype; restrict in production) |
| GET | `/api/auth/me` | Current authenticated user |

## Inspections

| Method | Path | Description |
|---|---|---|
| POST | `/api/inspections` | Create an inspection (product/brand/category/location/notes) |
| POST | `/api/inspections/{id}/images` | Multipart upload: `files[]` + `categories[]` (one category per file, same order) |
| POST | `/api/inspections/{id}/analyze` | Runs the full pipeline: preprocessing → OCR → extraction → rules → findings/evidence |
| GET | `/api/inspections` | List, with query params `search`, `status`, `category`, `officer_id` |
| GET | `/api/inspections/{id}` | Full inspection detail, including `images[]` |
| GET | `/api/inspections/{id}/results` | Declarations + rule-by-rule compliance checks (with nested findings/evidence/verification) |
| GET | `/api/inspections/{id}/findings` | Just the findings for this inspection |
| GET | `/api/inspections/{id}/evidence` | Evidence records for this inspection's findings |

## Findings / Verification

| Method | Path | Description |
|---|---|---|
| GET | `/api/findings/{finding_id}` | Finding detail |
| POST | `/api/findings/{finding_id}/verify` | `{decision: CONFIRMED\|REJECTED\|MODIFIED, corrected_value?, remarks?}` — stores a **separate** `VerificationRecord`; never overwrites the automated result |
| PUT | `/api/findings/{finding_id}` | Alias of verify, kept for REST completeness |

## Reports

| Method | Path | Description |
|---|---|---|
| POST | `/api/reports/{inspection_id}/generate` | Generates a PDF, returns `{report_id, file_path}` |
| GET | `/api/reports/{report_id}/download` | Downloads the PDF |

## Rules (ADMIN only for write)

| Method | Path | Description |
|---|---|---|
| GET | `/api/rules` | List all rules |
| GET | `/api/rules/{id}` | Rule detail |
| POST | `/api/rules` | Create a rule |
| PUT | `/api/rules/{id}` | Update a rule |
| DELETE | `/api/rules/{id}` | Soft-deactivate (never hard-deletes, to preserve audit history) |

Rule shape:
```json
{
  "rule_code": "LMPC-MRP-01",
  "rule_name": "Maximum Retail Price (MRP) declaration present",
  "category": "MRP",
  "validation_method": "REQUIRED_PRESENT",
  "validation_params": "{}",
  "reason_template": "MRP declaration detected: {value}",
  "version": "LMPC-2011-R1",
  "legal_reference": "LMPC Rules 2011, Rule 6(1)(e)",
  "status": "ACTIVE"
}
```
`validation_method` is one of `REQUIRED_PRESENT`, `REGEX_MATCH`,
`NUMERIC_RANGE`, `NOT_APPLICABLE`. `validation_params` is a JSON string,
e.g. `{"pattern": "..."}` or `{"min": 1, "max": 1000}` or
`{"applicable_categories": ["food", "beverage"]}`.

## Dashboard

| Method | Path | Description |
|---|---|---|
| GET | `/api/dashboard/stats` | Totals, breakdown by status/category, 10 most recent inspections |

## Demo mode

| Method | Path | Description |
|---|---|---|
| GET | `/api/demo/cases` | List the 4 built-in demo cases |
| POST | `/api/demo/{case_key}/run` | Generates a synthetic package-label image for the case and runs the **real** pipeline on it end-to-end |

Demo cases: `mostly_compliant`, `missing_declaration`, `format_issue`,
`poor_quality`. Every demo inspection is flagged `is_demo: true` — only the
input "package photo" is synthetic; OCR, extraction, rules, findings, and
evidence all run for real against it.

## Status vocabulary

Check status: `PASS`, `POTENTIAL_NON_COMPLIANCE`, `NEEDS_VERIFICATION`, `NOT_APPLICABLE`.
Overall inspection status: `PENDING`, `PROCESSING`, `COMPLIANT`, `POTENTIAL_NON_COMPLIANCE`, `NEEDS_OFFICER_VERIFICATION`, `FAILED`.
Officer decision: `CONFIRMED`, `REJECTED`, `MODIFIED`.
